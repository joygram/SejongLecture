# 데이터 글쓰기 실습 — 에이전트 규칙

이 폴더에서 일하는 코딩 에이전트는 아래를 항상 지킨다.

## 과제
- 질문: 2026년 국가공무원 7급 공채 1차 필기의 직군별·모집단위별 경쟁 규모는 어떠한가
- 자료: 공공데이터포털 「인사혁신처_국가공무원 7급 공채 1차 필기시험 응시현황 통계」
- 지표: 경쟁률 = 응시 ÷ 선발예정 (분모는 DECISIONS.md의 결정을 따른다)
- 다른 질문·자료로 바꿀 때는 이 절만 고친다

## 항상 지킬 것
- 숫자를 지어내지 않는다. 자료에서 확인하지 못한 값은 멈추고 알린다
- 원본은 raw/에 손대지 않고 그대로 둔다
- 쉼표만 지운다. '-'·빈칸·기호는 0으로 바꾸지 않고 원문 값을 따로 열에 남긴다
- 평가("인기", "선호", "어렵다")와 원인 추측을 쓰지 않는다. 숫자에 보이는 것만 쓴다
- 그래프 축은 0부터, 단위를 표시한다
- 리포트 본문 숫자는 인라인 코드로 계산한다. 손으로 친 숫자는 없다
- 단계마다 실행한 명령과 결과를 짧게 보여 준다

## 작업 순서
- A 환경: node·npm·python·pip·quarto 확인. python이나 quarto가 없으면 설치 방법을 알리고 멈춘다
- A 환경: pandas·matplotlib·openpyxl·pdfplumber·jupyter 설치, matplotlib 한글 글꼴 지정
- B 수집: 자료를 내려받아 raw/에 저장. CSV는 그대로, PDF는 pdfplumber, HWPX는 압축을 풀어 표를 꺼내 data.csv로
- B 수집: 합계·소계 행을 아래 행들의 합과 대조해 결과를 보인다. 다르면 멈춘다
- B 수집: 자료 이름·기관·주소·기준일·조회 날짜·꺼낸 방법을 SOURCE.md에 적는다
- C 점검: 판단이 필요한 자리를 CHECK.md에 표로 적는다 (판단할 자리 / 데이터에서 보인 숫자 / 사람이 답할 질문)
- C 점검: 최소한 분모, '-' 칸, 합계 행과 이중 집계, 구분모집, 아주 작은 단위, "가장 ○○한" 같은 표현을 본다
- C 점검: DECISIONS.md에 항목마다 선택지와 빈 "결정 =", "근거 =" 칸을 만든다
- D 리포트: 사람이 "진행해"라고 할 때만 시작한다
- D 리포트: DECISIONS.md에 빈 칸이 있으면 그 항목만 알리고 멈춘다
- D 리포트: 결정대로 수식이 들어간 sheet.xlsx와 report.qmd → report.html을 만든다
- D 리포트: 구성 = 요약, 질문, 자료와 방법, 결과(표·그림 번호와 캡션), 판단 기록, 자료의 한계, 재현 정보
- D 리포트: 마지막에 리포트 숫자를 data.csv로 다시 계산해 대조한 표를 보인다

## 멈출 자리
- C를 마치면 멈추고 사람에게 DECISIONS.md를 채우라고 말한다
- 분모·포함 범위·빈칸 해석·표현은 에이전트가 정하지 않는다. 기본값도 넣지 않는다
- 파일을 지우거나 폴더 밖을 건드려야 하면 먼저 묻는다

## 기록
- 출처 = SOURCE.md, 판단할 자리 = CHECK.md, 사람의 결정과 근거 = DECISIONS.md
- 리포트 끝에 AI 사용 사실을 밝힌다

- 내가 첨부하거나 붙여넣은 자료만 쓴다. 자료에서 확인하지 못한 숫자는 [확인 필요]로 둔다.

- 답 끝에 "이 답에서 자료에 없는 숫자" 목록을 붙인다. 없으면 "없음".

자료 간 차이같은 숫자가 다른 공식 자료에서 다르게 나오지 않나
표현"가장", "인기", "어렵다"가 숫자에 있나

바로 해 볼 수 있는 공개 자료: 인사혁신처 국가공무원 공채 응시·합격 통계(PDF·HWPX), 한국산업인력공단 직무분야별 기사·기능사·기술사 자격통계현황(CSV). 공공데이터포털에서 "인사혁신처 공채", "자격통계현황"으로 찾습니다.

# 강의 슬라이드 제작·검수 프롬프트

## 입력
- 주제 = {{주제}}
- 청중 = {{청중}}
- 시간 = {{시간}}
- 원하는 변화 = {{목표}}
- 설계 정본 = 사용자 제공 개요·원자료.

## 내용 설계
- 확정된 일정·목표·데이터 범위 유지.
- 팀 과제의 시작부터 보고서 완성·팀 채팅 공유까지 같은 주제·원자료·문단을 이어서 사용.
- 사례를 이해하기 어렵다고 다른 가상 데이터로 바꾸지 말고, 노출 목적에 필요한 정보만 고름.
- 장별 핵심 메시지 한 개, 청중이 할 행동 한 개 이내.
- 본문 = 청중의 이해·질문·실습·출처에 필요한 정보.
- 발표자 노트 = 시간 배분·멘트·전환·파일 경로·터미널 명령·네트워크 대안·제작 지시.
- 구현 파일명은 학습 대상일 때만 노출, 내부 운영 절차는 발표자 노트로 이동.

## 이야기와 일러스트
- 도입 = 학부생이 공감할 가상 상황 한 개, 실제 사례·실제 모델 응답으로 오인되지 않게 표시.
- 같은 가상 팀·질문 유지; 프레젠테이션은 AI로 통일; 세롱이 이름·로고는 원샷 결과물에서만 사용.
- 이미지 = 실제 자료나 행동을 설명하는 시각물; 다른 로봇·가상 막대로 과제·실제 수치를 대신하지 않음.
- 확정 시간표 유지, 같은 결론·문구의 반복 장은 합침.
- 일러스트 = 본문의 개념을 설명하는 장에 배치, 수치·문구는 편집 가능한 실제 텍스트로 유지.
- 생성 이미지 = 프로젝트 assets에 저장, 실제 통계 차트를 대신하지 않음.

## 시각 설계
- Quarto revealjs 원본과 SCSS에서 수정, 생성 HTML 직접 수정 금지.
- 기준 캔버스 1280×720, 16:9, 창 크기에 비례 축소.
- 한 장씩 표시, 모바일 자동 스크롤 전환 끔, 전체 페이지 번호·조작 안내 대신 하단 3px 진행 게이지만 표시.
- 아이보리 #f8f6f0 / 청록 #147d78 / 진한 녹색 #183b3b / 황토 #dfa158.
- 본문 약 23–24px 이상, 제목 약 37px 이상, 정보 과밀 시 내용 분할.
- 역할·목표 = 3개 카드, 4요소 = 2×2 카드, 전후 비교 = 동일 폭 2열.
- 절차 = 연결된 단계, 정확한 수치 비교 = 표·차트, 결론 = 한 줄 강조.
- QR = 독립된 우측 칸, 본문과 겹침 금지, 실제 링크와 판독 확인.
- QR = 카드 설명이 모두 끝난 뒤 별도 직접 해보기 화면에 1개 배치; 다른 실습·시연·공유 화면에는 반복 배치 금지.
- 장식보다 읽기 순서·대비·여백·강조 우선, 색만으로 정오 구분 금지.

## 정확성·노출 검수
- 숫자 = 원자료와 계산식 대조, 추측한 원인·출처·인용 생성 금지.
- 예시 오답 = 오류를 넣은 예시로 명시, 실제 관측한 답처럼 표현 금지.
- 본 강의 = 분야·시험 본 인원만 사용, 경쟁률·응시율·분모·통계 계산 설명 제외.
- 표·그림·문장이 같은 정보를 담는지 확인하고, 사실과 내 추측을 구분.
- 클릭 이동 = 본문·이미지 클릭 다음, Shift+클릭 이전, 링크·메뉴·선택 텍스트 조작 제외.
- 발표자 노트는 원본·로컬 워크벤치에만 보관, audience-only.lua로 공개 HTML에서 제거.
- 장별 노출 정보·시각 형식·검수 결과를 워크벤치에서 확인.

## 완료 조건
- python slides/workbench.py build → python slides/workbench.py check 실행.
- 전 장 1920×1080 / 1366×768 / 1024×768 / 390×844에서 잘림·하단 침범·깨진 이미지 점검.
- 표지·카드·표·차트·QR 장의 실제 스크린샷 검토.
- 자동 검사와 사람 검수를 구분, 미확인 항목은 미검증으로 표시.
- 도구 이름·메뉴 설명은 보조 가이드로, 본문은 아이콘을 이용한 활용 흐름 한 장으로 정리.
- 청중용 HTML·제작 프롬프트·워크벤치·시연 입력·예상 질문·남은 검수 항목 전달.

## 글쓴이의 생각
- 화면마다 보여주는 이유와 사람이 생각할 질문을 발표자 노트에 기록.
- 문체를 전문적으로 꾸미는 것보다 글쓴이의 목적·관심·선택이 드러나게 수정.
- 수정 전후는 같은 글에서 무엇을 왜 바꿨는지 설명, 준비한 예문과 실시간 AI 응답 구분.

## 문장 점검
- 청중을 달래는 상투적 진행 문구 삭제: 괜찮아요·가볍게·함께 해봐요·남겨보세요.
- 슬라이드 = 실제 질문·사례·변경 전후, 발표 멘트 = 발표자 노트.
- 출처는 자료 성격 명시: 실무 글·공개 연구 원고·심사 논문 구분, 참고자료를 네 요소의 제창 근거로 격상하지 않음.


## 문체와 결언
- 본문 = 짧고 직접적인 요체, 실제 질문과 구체적인 수정 전후 중심.
- 강사 말투 = “그래서 무엇을 말하려는가”, “이걸 믿을 근거가 있는가”를 묻는 방식.
- 훈계·과장·막연한 격려 배제, 학생에게 판단을 요구하는 질문으로 마무리.
- 결언 = “글은 AI가 썼는데, 판단은 누가 한 거죠?”
- 교과 연결 = AI위험과 정책결정론; 글의 근거·빠진 관점·타인의 선택에 미치는 영향.

## 실제 제작 기여와 확인 상태
- 강사 = 청중·목적 설정, 구성·표현 수정 지시.
- AI = 초안·자료 정리·구현·자동 점검; 강사의 직접 검증과 구분.
- 강사 직접 검증 = 대부분 미실시, 실제 확인 기록이 생긴 항목만 갱신.
- 결언 하단에 제작 범위와 미확인 상태 공개, 가상 실습 기록과 실제 제작 기록 구분.

## 이야기 연결
- 시작 질문 = 사람이 많은 분야를 인기 있는 분야라고 써도 되는가.
- 팀원 = 사례 속 인물; 표현의 효과를 설명할 때는 보는 사람으로 지칭.
- 표 → 정확한 인원, 그림 → 강조할 관점, 문장 → 자료로 말할 수 있는 범위.
- 같은 질문 = 어느 분야에 실제 시험을 본 사람이 많았고, 이것을 인기라고 설명해도 되는가; 초안·실습·보고서·팀 채팅까지 유지.
- 용어 = 보고서, 응시인원(실제로 시험을 본 사람 수), 표·차트·문장, AI 글쓰기 도우미 세롱이.
- 시연 공개 = 미리 준비한 수집·제작 코드 사용을 본문에 명시; 실시간 요청·실행·검토와 사전 준비 구분.
- 카드1 = 30–38분, 카드2 = 38–46분, 강사 시연 = 46–54분, Q&A = 54–60분; 카드3 전체 실습은 집에서.
- 차트 = 같은 수치·축·순서에서 제목과 강조 비교, 오류 찾기로 대체 금지.

- 독자 = 일반 독자; 팀원은 공동 작성자·검토자, 보고서 독자와 구분
- 출발 = 인기 분야가 궁금하다는 평범한 관심; 자료 대조·해석 한계는 글을 쓰며 발견
- 요청 예시 = 역할·상황·제공한 재료·작업을 명시한 지침; [자료 확인 후] 표시·요체 지정 문구 제외
- 표현 = A/B 고르기보다 보고서에서 포커스하려는 모습과 차트 모양·강조의 관계 설명
- 운영 = 시간표·강사 시연 시나리오를 청중 본문에 넣지 않음; 작업 방식을 지시하는 원샷 프롬프트의 내용 제시
- 사람 역할 = 길잡이와 판단은 사람이 함

- 서론 = 메모의 관심·질문을 정리; 데이터 사용 일괄 금지 지시를 넣지 않음, 사용한 수치·사실의 출처 확인

- 시각 정돈 = 기존 종이·잉크·문구류 모티프와 일러스트 유지; 내용 수정 때문에 시각 요소 일괄 제거 금지
- 표·차트 활용 = 비교 목적을 소개하는 문장·표에서 짚을 수치·차트로 드러낼 모습의 실제 본문 예시 제시
